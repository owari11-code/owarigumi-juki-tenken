# GENBA ONE by OWR（現場管理クラウド）

株式会社尾割組の現場管理システムです。重機点検アプリ「マル点」を土台に、次の機能をひとつにまとめました。
（旧称「マル点クラウド」。2026年9月に **GENBA ONE by OWR** へ名前を変えました）

| 分野 | できること |
|---|---|
| 点検 | 重機・足場・玉掛け・地山/土留の点検をQRから記録。元請（現場代理人・主任技術者）の確認、月間点検表・足場点検表の印刷 |
| 資材 | 資材ごとのQRで搬入・使用・搬出・棚卸を記録。在庫数の自動計算、発注点のお知らせ、受払簿の印刷 |
| 重機 | **ホームの「重機」タブ**に全社の重機・機械が並びます。持出先の現場を選ぶと、その現場の「機械」「点検」にも出ます。特定自主検査・車検・保険の期限をお知らせ |
| 工具 | 工具ごとのQRで持ち出し・返却を記録。保管場所は土場・本社から選択。返却期限切れのお知らせ、貸出簿の印刷 |
| 工程 | 工程表の上でドラッグして工種の期間・進捗を入力。全体の進捗率（予定・実績）と出来形（Sカーブ）。**実施工程表の様式でExcelに出力** |
| 人員 | 社員名簿、現場への配置、月間の配置表（重複・未配置の確認）。配置の帯をタッチすると、配置期間の明細が開きます |
| KY | リスクアセスメントＫＹ活動表（社内様式）。現場のQRから作成、A4横で印刷 |
| 入場者 | 新規入場者調査票（参考様式第4号）。現場のQRから記入、事務所で一覧・印刷 |

**自筆の欄**（KY活動表の参加者、新規入場者調査票の回答者サイン）は、
欄をタッチすると全画面に広がり、指・タッチペン・マウスで署名できます。
保存するのは画像ではなく線の通り道なので、1人分が1KB前後で、拡大しても印刷してもぼやけません。

新規入場者調査票の**資格の欄**は、愛知県 土木工事現場必携（令和8年4月版）と法令をもとに作り直してあります。
出典は [`public/js/data/licenses.js`](public/js/data/licenses.js) の冒頭に書いてあります。

## しくみと安全対策

```
スマートフォン／パソコン
   │  画面（public/）。データは端末内（IndexedDB）にも保存し、圏外でも記録できる
   │
   │  /api/...  （同じドメインだけ。別サイトからの呼び出しは拒否）
   ▼
Cloudflare Worker（src/）
   │  ・事務所：ログインの証明（署名付きクッキー）を確かめる
   │  ・現場　：QRの鍵から作った証明を確かめ、その現場の範囲に絞る
   │  ・Turnstile で自動化された大量アクセスを遮断
   │  ・データベースの鍵はここだけが持つ（ブラウザには渡さない）
   ▼
Supabase（PostgreSQL）
      juki_records   … 全データ（種別ごと）。削除は「削除済みの印」だけ
      maruten_users  … 事務所アカウント。パスワードは bcrypt で暗号化し、照合もDBの中だけ
```

主な対策

- **データベースの鍵はブラウザに渡さない**（Cloudflare の Secret にだけ置く）
- **事務所はID＋パスワード**。5回続けて間違えると15分ロック。無効化・権限変更・パスワード変更は、ログイン中の端末にもすぐ反映
- **現場はQRの鍵**。鍵を作り直すと、古いQRで入っていた端末はすぐ使えなくなり、その端末に残っていたデータも消える
- **現場の端末に渡さないもの**：社員名簿・工程・配置・QRの鍵・社内メモ、よその現場のデータ、62日より前の点検記録
- **新規入場者調査票は「書けるが読めない」**。現場の端末から送ることはできますが、読み出すことはできません。
  送り終えた調査票は、その端末からも消えます（住所・生年月日・緊急連絡先を現場に残さないため）
- **現場の端末から書けないもの**：登録内容の変更・削除・元請の確認・よその現場や別の資材を参照する記録
- **元請の確認は本人の名前でしか付けられない**（他人の名前での確認はサーバーが拒否）
- 画面には CSP などのセキュリティヘッダーを付与（`public/_headers`）

## 導入手順（旧アプリからの切り替え）

今お使いの Cloudflare の Worker（`owarigumi-juki-tenken`）とデータベースを、そのまま使います。
**既存の点検記録はそのまま引き継がれます。** URLも変わりません。

### 1. データベースの準備（Supabase）

1. Supabase の管理画面を開く。プロジェクトが **一時停止（Paused）** になっていたら **Restore** を押して再開する
2. **SQL Editor** → **New query**
3. `sql/setup.sql` の中身を全部貼り付けて **Run**
4. 最後に表示される **「初期設定コード」** を控える（24時間有効・1回限り）

何度実行しても壊れません。コードの期限が切れたら、もう一度 Run すると新しいコードが出ます。

> **無料プランは、しばらく使わないと自動で止まります。** 止まっている間は、アプリに
> 「データの保管先（Supabase）に接続できません」と出ます。管理画面の **Restore** で戻ります
> （データは残っています）。GitHub Actions の「稼働確認」が失敗していたら、これが原因です。

### 2. Cloudflare の設定（確認だけ）

Worker の **Settings → Runtime variables and secrets** に、次の4つが **Secret** で入っていること。

| 名前 | 内容 |
|---|---|
| `SUPABASE_SERVICE_KEY` | Supabase の secret キー（`sb_secret_…`） |
| `SESSION_SECRET` | 署名用の長いランダムな文字列 |
| `TURNSTILE_SECRET` | Turnstile の Secret Key |
| `KEEPALIVE_TOKEN` | 自動アクセス用の合言葉（GitHub の Secret と同じ値） |

`SUPABASE_URL` と `SPACE` は `wrangler.jsonc` に書いてあるので、画面での登録は不要です。

### 3. 新しいファイルを公開

GitHub のリポジトリを、このフォルダの内容に置き換えます（古い `index.html`・`js/`・`css/`・`functions/`・`worker.js` などは削除）。
Cloudflare が自動で組み立て直し、数分で公開されます。

### 4. 最初の管理者を登録

1. アプリを開く → 右上 **事務所ログイン** → 下の **「初期設定はこちら」**
2. 手順1の **初期設定コード**、ID、氏名、パスワード（10文字以上）を入力

ここで登録した人が管理者です。**設定 → 事務所アカウントの管理** から、ほかの社員のアカウントを作ります
（仮パスワードを伝え、初回ログインで本人が変更します）。

### 5. QRコードの印刷

以前のQRコード（`#i=` 形式）は使えなくなります。各現場の **QR** タブから印刷し直してください。

- **現場QRコード（掲示用）**：詰所・朝礼の場所に掲示
- **点検対象のQRラベル**：重機・足場・クレーン・掘削箇所に貼付
- **資材・機械のQRラベル**、**工具のQRラベル**（工具の画面から）

## 工程表の使い方

工程は、画面の工程表を直接さわって作ります（現場のタブ →「工程」）。

工程の行は、請負代金内訳書と同じ3段で持ちます。

| 段 | 呼び方 | 例 | Excelのどこに入るか |
|---|---|---|---|
| 大分類 | **工種** | 砂防土工 | 左端の「工種」欄（同じものが続くと縦に1つにまとまります） |
| 中分類 | **種別** | 掘削工 | 「種別」欄 |
| 小分類 | **数量** | 50.0 m3 | 「数量」「単位」欄 |

| したいこと | 操作 |
|---|---|
| 行を追加する | 一番下の行に **工種（大分類）** と **種別（中分類）** を入れて、その行を横にドラッグ（その期間で追加）。または ＋ を押す |
| 期間を前後にずらす | 帯の真ん中をドラッグ |
| 開始日・終了日を変える | 帯の左端・右端をドラッグ |
| 進捗（%）を変える | 帯の中の□を左右にドラッグ（5%きざみ） |
| 工程を組み替える（変更） | 種別名の右の **「変」** を押すと、緑の帯ができます。緑をドラッグして変更後の期間に合わせてください。もう一度「変」を押すと取り消せます |
| 広く使う | **「大きく表示」** を押すと、工程表が画面いっぱいに広がります。そのままドラッグで編集できます |
| 行の並びを変える | 行の左の **▲▼** でひとつずつ上下に動かせます。行の並びは、**予定を前後に動かしても入れ替わりません**（並べた順のままです）。日付の順にそろえ直したいときは **「日付順に並べ直す」** を押してください |
| 細かく直す | 種別名をクリック（金額・数量・備考・実績日を入力） |

**実施工程表をExcelに出力**を押すと、2枚のシートができます。

**① 実施工程表**　社内でお使いの様式に合わせています。

```
実　施　工　程　表
工事名／工期（和暦）
┌──────┬────┬──┬────┬──────────────────┬────┐
│工種・種別 │数量・単位│  │構成比率│  年度／月／日のマス目      │摘要 │
├──────┼────┼──┼────┼──────────────────┼────┤
│砂防土工 掘削工│ 50.0 m3│  │ 0.3 │ ━━━━  100(0.3)   ←予定（黒）│凡例 │
│       │      │  │    │ ━━━   100(0.3)   ←実績（赤）│    │
│       │      │  │    │   ／出来高曲線（予定＝黒・実績＝赤）│    │
├──────┴────┴──┴────┼──────────────────┼────┤
│全体（金額）工程        100%│計画 1.60%  8.50% …／実施 6.70% …│    │
└───────────────────┴──────────────────┴────┘
```

- 左に**工種・種別・数量・単位・構成比率**、右に**月日のマス目**
- **予定＝黒の帯／変更＝緑の帯／実績＝赤の帯**。帯の右に `進捗%(出来高%)` を表示（変更は、入れた工種があるときだけ行が増えます）
- マス目の上に**出来高曲線**（予定＝黒、変更＝緑、実績＝赤）を重ねています（Excelの本物のグラフ）
- 下に**全体（金額）工程**の月ごとの計画・実施の累計％
- 用紙はA3横・1ページに収まる設定です

**② 出来形**　日付ごとの予定・実績と折れ線グラフ。①の曲線は、このシートの数字を見ています。

進捗を保存するたび、その日の全体進捗が記録され、出来形の折れ線（実績）になります。

### 請負金額と構成比率

**構成比率 ＝ 積算金額 ÷ 純工事費（全体金額）** で出します。

| 現場に入れる金額 | 何に使うか |
|---|---|
| 請負金額 | 契約の金額（税込）。参考の表示に使います |
| **純工事費** | **構成比率の分母（全体金額）**。直接工事費＋共通仮設費 |
| 共通仮設費 | ここから「準備工」「後片付」の金額を出します |

**準備工・後片付**は内訳書の工種の中に無いため、**共通仮設費を割り振って**作ります。
割合（はじめは50:50）は、工程の画面の「準備工・後片付」でいつでも変えられます。
変えると、2つの行の金額と構成比率がその場で入れ替わります。

金額は1件ずつ入れてもよいのですが、**請負代金内訳書（様式第22）のExcelをそのまま読み込めます。**

1. 現場のタブ →「工程」→ **請負代金内訳書を読み込む**
2. 内訳書の `.xlsx` を選ぶ
3. 「費目・工種・種別・細別」の段組みを読み取り、いちばん細かい段を1行ずつ並べます
   （工種＝1つ上の段の名前、種別＝その行の名前、積算金額＝金額の欄）
4. 全体金額（＊＊純工事費＊＊）・請負金額（＊＊合計＊＊）・共通仮設費が自動で選ばれます。
   準備工の割合を決め、取り込む行にチェックを入れて **取り込む**

取り込んだ合計が全体金額とそろっていれば、構成比率の合計は100%になります
（画面にも「そろっています」と出ます）。

期間は工期を等分した仮の値で入ります（準備工は工期の頭、後片付は工期の終わり）。
取り込んだあと、帯をドラッグして合わせてください。

**様式を埋めるために使う欄**

| Excelの欄 | どこで入力するか |
|---|---|
| 工種（左端） | 行の編集 →「工種（大分類）」（例：砂防土工）。同じものが続くと、縦に1つにまとまります |
| 種別 | 行の編集 →「種別（中分類）」（例：掘削工） |
| 数量・単位 | 行の編集 →「数量（小分類）」「単位」 |
| 構成比率(%) | 「積算金額 ÷ 純工事費」で計算。純工事費が空欄のときは入力した金額の合計を分母にし、金額も無いときは「重み」を使います |
| 変更（緑） | 工程表の「変」ボタン、または工種の編集 →「変更（開始）／（終了）」 |
| 工事延長 | 現場の編集 →「工事延長・数量」 |

空欄のままでも出力できます（その欄が空になるだけです）。

## ログインできないとき

**パスワードは元に戻せません。** 暗号化して保存しているためで、これは仕様です。
思い出すのではなく、**新しいものに作り直します。**

### ほかの管理者がいる場合（いちばん簡単）

その人に **設定 → 事務所アカウントの管理** を開いてもらい、対象のアカウントの
**「パスワードを再発行」** を押してもらってください。仮パスワードが表示されるので、
それでログインし、画面の案内どおり新しいパスワードを決めます。

### 管理者も入れない場合（Supabaseから）

Supabase の管理画面 → **SQL Editor** で、[`sql/recover.sql`](sql/recover.sql) を使います。

1. ファイルの上半分（`create or replace function public.maruten_reset_password …` から
   `revoke …` まで）を貼って **Run**（準備。1回だけでかまいません）
2. IDが分からなければ、「１．登録されているアカウントを見る」の `select` を実行
3. 「２．仮パスワードを発行する」の行を、先頭の `--` を外して実行

```sql
select public.maruten_reset_password('owari11') as "結果";
```

`ID：owari11（尾割順一）　仮パスワード：3F2A-9C41-B8D7` のように表示されます。
そのパスワードでログインすると、新しいパスワードの入力を求められます。

この操作で、**アカウントのロック解除・無効の解除**も同時に行われ、
**ほかの端末のログインは切れます**（乗っ取られていた場合の安全のため）。

> この関数を呼べるのは **Supabase にログインできる人だけ**です。
> アプリ側（インターネット側）からは呼べないようにしてあります。

そのほか、`sql/recover.sql` には次の手順も入っています。

| こんなとき | 使うもの |
|---|---|
| 管理者が1人もいなくなった | ３．管理者に戻す |
| アカウントが1つも無い | ４．初期設定をやり直す |

## 独自ドメインで公開する

いまのURL（`https://owarigumi-juki-tenken.owari11.workers.dev/`）は、Cloudflare の
Worker名から自動で決まるものです。独自ドメイン（例：`genbaone.com`）にすると、
**以後は名前を変えてもURLが変わりません。**

> **QRコードは貼り直しになります。** QRにはURLが埋め込まれているため、ドメインを変えると
> 貼ってあるラベル・掲示物が読めなくなります。切り替える日を決めて、印刷し直してください。

### はじめに：そもそもドメインとは

インターネット上の「住所」です。**買い切りではなく、1年ごとにお金を払って借り続けるもの**で、
払い忘れると他人に取られます。取る場所（レジストラ＝販売店）はどこでも同じものが届きます。

**先に確認してください。会社ですでにドメインをお持ちなら、新しく取る必要はありません。**
たとえば `owarigumi.co.jp` をお持ちなら、`genba.owarigumi.co.jp` のような
サブドメインを**追加費用なし**で使えます（手順は下の「B」と同じで、取得の手間だけ不要です）。

### どこで取るか（末尾によって変わります）

| | `.com` `.net` `.dev` など | `.jp` | `.co.jp` |
|---|---|---|---|
| 取れる場所 | **Cloudflare で直接**（いちばん簡単） | 日本の販売店（XServerドメイン、お名前.com など） | 同左 |
| 費用のめやす（1年） | 10ドル前後（原価販売。上乗せなし） | 2,000円前後 | 4,000円前後 |
| 手間 | ネームサーバーの設定が**要らない** | Cloudflare に追加して、ネームサーバーを変える作業が要る | 同左＋会社の審査（登記の確認） |
| そのほか | **Cloudflare は `.jp` を扱っていません** | 日本の会社らしく見える | 登記のある会社が1つだけ持てる |

**おすすめは `genbaone.com` を Cloudflare で取る方法です。**
理由は3つあります。

- Cloudflare の画面（いま使っているもの）だけで完結し、ネームサーバーの設定が要らない
- 原価で売っているため、更新のときに値上がりしない（日本の販売店は、1年目が安く2年目から高くなることが多い）
- Whois（持ち主の氏名・住所の公開）の代行が無料で最初から付く

現場のQRに入る文字数が短いほど読み取りが速いので、`genba-one` より `genbaone` のような
**短くて記号の無い名前**がおすすめです。

---

### A. Cloudflare で取る（`.com` など。所要 10分）

用意するもの：クレジットカード、Cloudflare のアカウント（いまお使いのもの）。

1. Cloudflare にログイン → 左のメニューの **Domain Registration** → **Register Domains**
2. 欲しい名前（例：`genbaone`）を入れて検索。緑で「Available」と出れば取れます
3. **Add to cart** → **Purchase**
4. 登録者情報を入れる（会社名・住所・電話・メール）。
   **メールは個人のものではなく、会社で見られるアドレスにしてください**（担当が代わっても届くように）
5. 支払い方法を登録して確定
6. 買った直後に **Auto-renew（自動更新）が ON** になっているか確認します
   （Domain Registration → Manage Domains → 対象のドメイン）

取得したドメインは、自動的に Cloudflare の管理下に入ります。**手順Bの作業は不要**です。
そのまま下の「アプリを新しいURLに切り替える」へ進んでください。

### B. 日本の販売店で取る（`.jp` `.co.jp`、または他社で取ったドメイン）

用意するもの：クレジットカード、会社の情報。`.co.jp` は登記簿の内容（商号・本店所在地）。

1. 販売店のサイトで名前を検索して申し込みます
   （[XServerドメイン](https://www.xdomain.ne.jp/domain/price.php)、
   [お名前.com](https://www.onamae.com/service/d-price/) など。どこで買っても同じものが届きます）
2. 申込みのときに **Whois情報公開代行**（持ち主の氏名・住所を隠す）を**必ずONに**します。
   後から有料になる会社もあるので、申込み時に付けてください
3. **自動更新をONに**します
4. 届いた **ドメイン認証メール**（ICANNからの確認）のリンクを必ず押します。
   放置すると15日ほどでドメインが止まります
5. Cloudflare にログイン → **Add a site** → 取ったドメインを入力 → **Free** プランを選ぶ
6. Cloudflare が2つの**ネームサーバー**（`xxx.ns.cloudflare.com` のような文字列）を表示します。
   これを、**1で申し込んだ販売店の管理画面**の「ネームサーバー設定」に貼り付けます
7. 反映までに数分〜1日かかります。Cloudflare の画面が **Active** になれば完了です

> **お名前.com などGMO系は、表示価格のほかに「サービス維持調整費」が上乗せされます**
> （2026年9月時点でおおむね26%）。申込み最終画面の**合計金額**を必ず確認してください。

### 取ったあと、必ず守ること

現場のQRコードがこのドメインを指すようになるため、**ドメインが切れると現場の記録が全部止まります。**

- **自動更新を必ずON**にしておく（いちばん大事）
- 登録メールは**会社で共有できるアドレス**にする（担当者の個人アドレスにしない）
- **クレジットカードを更新したら、ドメイン側の登録カードも更新**する
  （カード切れで自動更新が失敗するのが、失効のいちばん多い原因です）
- 更新期限を社内の予定表に入れておく

### アプリを新しいURLに切り替える

1. **Workerにドメインを割り当てる**
   Workers & Pages → `owarigumi-juki-tenken` → **Settings** → **Domains & Routes** →
   **Add** → **Custom domain** → 使いたいホスト名（例：`genbaone.com` や `app.genbaone.com`）を入力。
   証明書は自動で用意され、数分で `https://` で開けるようになります
2. **Turnstile に新しいドメインを足す**
   Turnstile → 対象のウィジェット → **Settings** → **Hostname Management** に、
   新しいホスト名を追加します（足さないと、ログイン時に「安全確認に失敗」＝コード110200 が出ます）
3. **アプリ側のURLを書き換える**
   `public/js/config.js` の `baseUrl` を新しいURLにして公開します。
   急ぐときは、各パソコンの **設定 → QRコードに入れるURL** に入れても同じ効果があります（その端末だけ）
4. **QRコードを印刷し直す**
   各現場の **QR** タブ、**重機**・**工具** の一覧から印刷して、貼り替えます
5. しばらく古いURLも生きています（workers.dev のアドレスは消えません）。
   貼り替えが済んだら、古いQRは処分してください

## 運用のヒント

- **圏外でも記録できます。** 記録はスマートフォンに保存され、電波が届いた時点で自動送信されます（右上に「圏外・未送信」と表示）。
- **QRコードの写真が外部に出回ったら**、その現場の **QR** タブで「QRコードを作り直す」を押し、印刷し直してください。
- **退職者のアカウント**は、削除せず「無効にする」を押してください。ログイン中の端末もすぐ使えなくなります。
- **完成した現場**は、削除せずに状態を「完成」にしてください（記録が残ります）。
